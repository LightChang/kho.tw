>
> **2026-09-14 加上地圖**：`/map.html` 顯示全台 1,782 個有座標的上課地點（涵蓋 19,671 門課、
> 其中 6,364 門招生中），並支援「找我附近的課」。圖磚用內政部國土測繪中心的臺灣通用電子地圖
> （政府資料開放授權條款－第1版），Leaflet 自帶不走 CDN——整站的外部連線只有圖磚一個。
> 座標精度只夠分辨到「哪一區」，所以「找附近」只給直線距離、不做路線規劃，介面上明講。
> TGOS 批次結果已回填：**有座標的課程從 21.5% 升到 59.4%**（20,017 門），場館 1,744／2,411。
>
> 回填後用「各縣市座標中位數」抽驗，抓到兩個疊加的缺陷：場館的名稱比對沒有限制縣市
> （名錄裡同名不同地址的場館有 750 組，「校本部」就有 104 個），臺東的課因此掛進
> 澎湖社大；補座標時又用課程自己的地址去查快取，把臺東的座標寫進澎湖的場館。
> 兩者都修掉之後，跨縣市的名稱比對 283 → 0，座標落在錯縣市的場館 12 → 4（影響 5 門課，
> 且都是來源資料本身把地址寫成別縣市，不是管線問題），澎湖的中位數從偏離 183 公里變成 1 公里。
>
> 修掉四個實際的資料缺陷：
> 1. 地址正規化沒處理「一段／1段」——同一座運動中心在兩份名錄裡對不到，全站 19.6% 地址用中文段號。
> 2. 分群沒讀職訓的 `externalIds.taiwanjobs`，職訓類的跨來源分群從頭到尾沒觸發過。
> 3. `mol-6060` 的「數量」其實是期別序號不是招訓人數，當成名額會讓首頁出現假的倒數。
> 4. 整條管線用 `toISOString()` 取日曆日，那是 UTC——台灣時間每天 0 到 8 點跑的資料全標成前一天，
>    而排程正好常在清晨跑。已改為台北時區（`transform/_date.mjs`）。
>
> 另有一項已修但要等外部資料才看得到效果：場館比對一旦命中名錄就不再查 `geocoded.csv`，
> 使得 7,796 門課即使門牌已有座標也補不上。TGOS 結果回來後，這項差距約 25 個百分點。

## 0. 一句話結論

這題和 seh.tw 是**同一個資料形狀**（場館 × 時段 × 分類 × 費用），但來源比文化部糟：**沒有任何一個 API**，全部是各單位網站的 HTML 查詢頁或 PDF／ODF 簡章。好消息是有三個「國家級匯總站」已經幫忙收了一輪（社大、樂齡、職訓），可以先從它們起步；壞消息是運動中心與圖書館完全沒有匯總層，要一家一家接。

## 2. 資料形狀的實況與問題

| 現象 | 例子 | 對架構的意義 |
|---|---|---|
| 課程是「期別」制，不是單日活動 | 社大分春／秋季（有些加暑期），運動中心 115-5 期 = 9–10 月，樂齡分春／秋季班 | event 要有 `recurrence`（每週幾、幾點到幾點、共幾週）而非只有 start/end；seh.tw 的 Event 型別要擴充或另立 `Course` 型別 |
| 報名有生命週期 | 新北樂齡：公告→線上報名→錄取→繳費→現場報名→開課，每階段有日期 | 一門課會產生多個時間點；「現在還能報名的課」是核心入口，需要 `enrollmentWindow` 欄位 |
| 名額是動態的 | 國圖「尚有名額場數」、運動中心「候補：如有釋放名額系統自動發信」 | observation 層每天重抓一次名額狀態就是產品（「還有位子的課」） |
| 課程開不成 | 社大查詢頁有「開課狀態：正常開課」，反面就是「不足額停開」 | `disappearedAt` 之外還要有 `cancelled` 狀態，來源自己會標 |
| 簡章是 PDF／ODF | 運動中心與產投方案課程 | 需要表格抽取；每期一份、每家格式不同，是最貴的解析工作 |
| 同一場館多種課程來源 | 一座運動中心的課由營運商發、館內講座由體育局發、旁邊圖書館又一套 | 場館 entity 是匯聚點，與 seh.tw 共用 venue pool 的價值就在這 |
| 分類標籤不一致 | 社大：學術／生活技能／社團；運動中心：泳訓／體適能／舞蹈；圖書館：講座／研習班；職訓：21 通俗職類；樂齡：核心／自主規劃／貢獻服務 | 需要一層跨來源的分類對照表（override），和 seh.tw 標題正規化是同一件事 |
| 對象限制 | 樂齡限 55+；產投方案限在職且需台灣就業通會員；部分社大課限設籍 | `audience` 欄位（一般／55+／在職／親子）是篩選必需，也是 SEO 長尾（「台中 樂齡 手機課」） |

## 3. 對應 seh.tw v2 架構

| seh.tw 概念 | 本題對應 | 差異 |
|---|---|---|
| Source ingest | 每個國家級匯總站一支；每家運動中心營運商一支；圖書館逐館 | 全是 HTML／PDF，沒有 API；來源改版偵測要做成一級功能 |
| Observation | 一筆 = (來源, 課程 id, 抓取日)，記錄名額／報名狀態／開課狀態 | 比活動更需要每日重抓，因為名額會變 |
| Cluster | 同一門課在國家級匯總站與縣市聯網、單位官網三處出現 | 規則：`源頭課程 id`(1.0) → `社大+課名+期別`(0.9) → `場館+時段+課名相似`(0.7) |
| Derived entity | 場館：先用「全國運動場館資訊」與社大名錄當種子，再從課程長出社大分校、里活動中心等教室 | 種子比 seh.tw 好，運動場館有官方座標 |
| Relation | 課程→場館、場館→營運商、場館→縣市、課程→分類、課程→講師（社大有老師名） | 「講師」是 seh.tw 沒有的 entity，社大老師跨校開課很常見，是不錯的 cluster 目標，但要注意個資（只用來源已公開的姓名） |
| Quality score / noindex | 有時段、有場館座標、有費用資訊、報名截止日未過 → index | 過期課程的頁面要留（SEO 與歷史）但降權 |
| 靜態頁 | 縣市頁、行政區頁、場館頁、分類頁、對象頁（樂齡／親子／在職）、「本週開放報名」頁 | 「現在可報名」是時間敏感頁，需要每日 build |
| 健康檢查 | 期別制造成**季節性斷崖**：學期間穩定、期末歸零、開報名日暴增 | 不能用 30% 掉幅規則；要按「期別週期」比較（今年秋季 vs 去年秋季） |

## 4. 規模估算（粗）

- 社大：全台約 90 所（⚠ 以 `/school` 實數為準），臺中一市一年 2,000+ 門 → 全台每季可能 15,000–25,000 門
- 樂齡中心：368 所（107 年數字），每所每季數門到數十門
- 運動中心：全台約 50–60 座（⚠ 用開放資料的「場館分類」篩），每期每館 50–200 門
- 圖書館：22 縣市 + 3 國家館，活動類（單場）為主
- 職訓：開放資料集 XML 一年數千筆

整體每季 3–5 萬門，**比 seh.tw 的 3,532 場活動大一個數量級**——切到「縣市 × 分類 × 週」仍有量，可解 seh.tw §8 的稀疏問題；但也代表 build 時間與頁數要重新估。

---

## 5. 開工前要親自量的

1. `cc.moe.edu.tw/course` 是否有 XHR JSON 端點、單次回傳上限、是否含場館地址與時段欄位（決定社大要不要走縣市級）。
2. 數清楚運動中心營運商：從「全國運動場館資訊」CSV 篩出運動中心，比對各縣市體育局列表的營運廠商欄位，得出「幾家營運商覆蓋幾座館」。
3. 抓一期救國團某館的簡章，評估 PDF 表格抽取的難度與穩定性。
4. 樂齡學習網各縣市子站是否有任何結構化課表，或全是公告附件。
5. 查 seh.tw 現有 70 個來源裡，哪些已經是圖書館／文化中心，避免重抓；確認 venue pool 是否能直接共用。
6. 「職業訓練課程資訊」XML 實際欄位與更新頻率；與台灣就業通查詢頁的差集有多大（產投方案是否值得另抓）。

以上 1、2、5、6 半天內可完成；3 與 4 是人工判斷。
