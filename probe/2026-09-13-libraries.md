# 縣市地方圖書館活動實測（2026-09-13）

站上原本只有國家圖書館（`ncl-events`，8 筆）與國立公共資訊圖書館（`nlpi-activities`，54 筆）兩個國立館，22 個縣市的公共圖書館活動一筆都沒有。本文逐縣市實測「有沒有結構化的活動／報名來源」，記錄端點、方法、格式、實測筆數、即時性、名額欄位與接不接的理由。體例接 `probe/2026-09-11-sources.md` 與 `probe/2026-09-13-unresolved.md`。

館別清單與座標一律以既有的 `national-public-libraries`（公共圖書館基本資料，22 縣市分組、攤平 616 館，含經緯度）為準。

---

## 0. 結論

1. **22 縣市裡真正可接的是少數，本輪接 2 支：臺南、新北。** 兩支都是館方自己的**報名系統**，不是新聞稿頁面——有報名起訖、報名狀態與名額欄位，正是本站要的東西。合計 143 筆 L1。
2. **「活動公告」和「活動報名」是兩種東西，投報比差很多。** 多數縣市圖的活動掛在政府網站 CMS 的新聞稿模組裡（北市圖、高市圖、彰化都是），欄位只有標題／內文／發布日：沒有活動日期欄位、沒有名額、沒有報名狀態，活動時間寫在內文的自由文字裡。相對的，臺南、新北有獨立報名系統，欄位是結構化的。**優先接報名系統，不要接新聞稿。**
3. **臺南市立圖書館有館方自己公開的 API**，這是這輪最好的發現：`https://www.tnpl.tn.edu.tw/api/ActivityList.ashx`，館方在「本館資訊API服務」頁公告，免登入、免金鑰、一次回全量，還附六個篩選參數。主活動→場次兩層結構，場次帶地點、講師、報名起訖、名額、報名狀態、是否收費。
4. **新北是本站少數拿得到「剩餘名額」的來源。** 列表每張卡片寫「已報名/名額 14/20」，兩個數字都在，相減就是剩餘。全台能給出剩餘名額的來源到目前為止只有軒恩系統、臺中社大聯網、南投、雲林，現在多一個新北市圖。
5. **南投縣沒有自己的縣立圖書館**，公共圖書館基本資料名錄裡南投的「總館」欄位指向**國資圖中興分館**，已經被 `nlpi-activities` 涵蓋，不必另接。
6. **北市圖有開放資料 RSS（100 筆）但沒有日期欄位，本輪不接。** 理由見 §2.1——它的活動日期只存在於內文自由文字，抽出來會錯。這是本輪唯一「量夠大卻放棄」的來源，補法也寫在那一節。

## 1. 已接的來源

### 1.1 `tnpl-activities` 臺南市立圖書館－活動報名

| 項目 | 內容 |
|---|---|
| 端點 | `GET https://www.tnpl.tn.edu.tw/api/ActivityList.ashx` |
| 方法 | 單次 GET，無分頁、無金鑰、免登入 |
| 格式 | json（`content-type` 標成 `text/plain`，內容是 JSON 陣列） |
| 實測筆數 | **49 個主活動 / 攤平 89 個場次**（2026-09-13） |
| 即時性 | 即時。報名狀態與報名起訖直接來自報名系統 |
| 名額欄位 | `可報名數` ＝ **總名額**（見下），無剩餘名額 |
| 建議 | **接**（已接） |

- 館方在「本館資訊API服務／活動報名資訊API」頁（`https://www.tnpl.tn.edu.tw/u5045404612791335735/a1`）公告這支 API，另有 `pav`（館別）、`evtKw`／`sesKw`（關鍵字）、`sesRegStart`／`sesRegEnd`、`sesStart`／`sesEnd` 六個**縮小範圍**用的參數。不帶參數就是全量，所以只發一次請求。
- 結構兩層：頂層「主活動」，底下 `本活動內各場次資訊` 陣列。報名、名額、時間、地點全掛在**場次**上，所以 L1 攤平成一場次一筆。
- 主活動欄位：`主辦單位`、`主活動資訊網址暨報名連結`、`主活動名稱`、`主活動主題`、`主活動對象`、`主活動主要說明`（HTML）、`主活動圖片`。
- 場次欄位：`場次名稱`、`活動時間`、`活動地點`、`活動說明`、`報名時間`、`可報名數`、`年齡限制`、`講師姓名`、`承辦人員資訊`、`是否收費`、`報名狀態`。
- 涵蓋 18 個館：總館 23（新總館 20＋公園總館 3）、鹽埕 4、台江文化中心 3、白河 3、下營 2、林森 2、新化 2，其餘 11 館各 1。
- 活動時間範圍 2026-08-15 ～ 2026-12-19。報名狀態分布：開放報名中 55、報名尚未開始 16、報名截止 18（89 個場次）。
- 對象分布：一般 21、嬰幼兒 12、兒童 5、樂齡 3、一般+樂齡 2，其餘混合。**成人向（一般／樂齡）合計過半**，符合本站守備範圍。

**名額語意（CONTRACT §5，已查證）**：`可報名數` 是**總名額**，不是剩餘。證據兩條：

1. 主活動 `za4976375043056165457` 的場次，API 回 `可報名數: "20"`；同一場次的活動頁寫「報名人數　正取人數： **5 / 20**」——20 是分母（總額），5 是已報名。
2. 89 個場次裡**沒有任何一筆是 0**，`報名狀態` 也從未出現「額滿」。若是剩餘名額不可能全部非零；且 18 筆已「報名截止」的場次 `可報名數` 仍是 5、12、24、40 這種整數。

來源沒有給已報名人數，剩餘算不出來，所以 L1 **只填 `capacity`、不填 `available`**。

### 1.2 `ntpc-library-activities` 新北市立圖書館－活動報名（atpass）

| 項目 | 內容 |
|---|---|
| 端點 | `GET/POST https://atpass.ntpclib.gov.tw/activities/8e109e8bb57a4b44b21e31c34db87dba` |
| 方法 | 列表頁 GET 取第 1 頁＋CSRF token＋cookie，其餘頁 POST 同網址翻頁 |
| 格式 | html（伺服器端算繪的卡片列表） |
| 實測筆數 | **54 個場次**（2026-09-13） |
| 即時性 | 即時。名額與報名狀態隨報名變動 |
| 名額欄位 | **「已報名/名額」兩個數字都有** → capacity 與 available 都填得出來 |
| 建議 | **接**（已接） |

- POST 參數：`csrfToken`、`_csrf`（同一個值送兩次，表單兩者都有）、`page`、`isPage=true`、`pageSize`、`orderField=registrationStart`、`orderType`。**token 每次執行重新取得，不可寫死**；還要帶列表頁發的 session cookie，少任一個都拿不到第 2 頁。
- **`pageSize` 伺服器端被夾在 10**：送 200 回來的頁面 `pageSize` 仍是 10、仍然「共 11 頁」，不能靠加大每頁筆數少發請求。
- ⚠ **「共 11 頁 × 每頁 10 筆」不等於 110 筆**。伺服器端分頁會重複吐同一列，有的單頁內部就出現兩筆一模一樣的（實測 asc 的 p5、p9、p11）。11 頁抓完去重後是 **54 筆**。這不是漏抓：以 `orderType=asc` 與 `desc` 各抓 11 頁，兩邊各自去重都剛好 54 筆、**聯集也是 54 筆**，兩個方向看到的是同一組場次。所以本支以「跨頁去重後的集合」為結果，不用頁數 × 每頁筆數推估。
- 一列是一個**場次**（同一活動不同場次各有日期與名額）。欄位：活動名稱、場次名稱、活動日期、節錄、已報名/名額、候補名單、報名起訖日、狀態文字。
- ⚠ **場次 id 只有還能報名的卡片才有**（`showSessionDetail('<32 hex>')`），已額滿的卡片只有一張圖片、沒有這段 JS。實測 54 筆裡 46 筆有 id、8 筆沒有；沒有的改用「活動｜場次｜日期」雜湊當穩定鍵。
- 狀態分布：我要報名 46、已額滿 8。剩餘名額分布：0 名 16 筆、>0 共 38 筆（最大 296）。
- 場館：活動標題開頭的【】就是館別（【淡水分館】、【總館】）。名錄比對後 54 筆裡 **49 筆帶得出座標**；對不到的是「五股守讓堂」（古蹟館舍，不在公共圖書館名錄）2 筆與【全市】跨館活動 3 筆。
- **候補名單不併進 `available`**——候補不是空位。

## 2. 六都其餘四市：實測與不接的理由

### 2.1 臺北市立圖書館：有 RSS、有量，但**沒有活動日期欄位**

- 正確網域是 **`tpml.gov.taipei`**（`tpml.gov.tw`／`www.tpml.edu.tw` 都 DNS 查不到）。
- 開放資料端點：`GET https://tpml.gov.taipei/OpenData.aspx?SN=24C1A4661875547B`，`content-type: text/xml`，RSS 2.0，**實測 100 筆**，channel title「臺北市立圖書館藝文活動」。網頁端對應 `News.aspx?n=3951678DEC0A8461&sms=9D72E82EC16F3E64`（12 頁 × 20 筆）。
- 另外兩個 SN（`4BB77B3010D6BADB`、`E8B74B7812BC6703`）**回 404**，頁面上標的 XML／JSON 版本實際上取不到。`News_Json.aspx`／`News_Xml.aspx`／`News_Rss.aspx` 也都 404。
- **item 只有四個子標籤：`title`、`link`、`description`、`pubDate`。** 沒有活動起迄、沒有地點、沒有名額、沒有報名狀態。`pubDate` 是**發布日**不是活動日。
- 分館可辨識度不錯：標題幾乎都帶館名，用名錄比對（加上「總館」別名）**81/100** 對得到分館與座標。
- **不接的理由在日期**：活動日期只存在於 `description` 的自由文字。實測「標籤式日期」（`活動時間：9月15日` 這種）只有 **56/100**，而且其中 **48 筆該篇出現不只一個日期**（月節目表、系列講座場次表，最多一篇 10 個日期）。取第一個就會把課掛到錯的日子，違反 §5「分不清楚就不要填」的同一個精神。L1 的 `schedule.startDate` 是必填，硬湊等於整批資料日期不可信。
- **建議補法**（下一輪）：不要從 RSS 補，改抓 `News_Content.aspx?…&s=<id>` 詳情頁，或改用北市圖的**活動報名**子系統（首頁「線上申請／活動報名」）——報名系統才有結構化的日期與名額。這支值得再花時間，因為它是全台分館最多的市圖之一（名錄 57 館）。

### 2.2 桃園市立圖書館：列表只出得來 12 筆，分頁解不開

- `GET https://www.typl.gov.tw/zh-tw/Activity`，伺服器端算繪，**一次只有 12 個活動**（`/zh-tw/Activity/Content/<id>`）。
- `?page=2`、`?Page=2`、`?p=2`、`?page=2&PageSize=12` **四種寫法回的內容完全相同**（同樣那 12 個 id），分頁不是靠 query string。
- `/zh-tw/RSS/Activity` 名字叫 RSS，實際回的是 `text/html` 首頁（206 KB，0 個 `<item>`）——**不是 feed**。
- 頁面上找得到的 AJAX 端點只有 `/zh-tw/Home/GetVenues`、`/zh-tw/Home/GetClosed`（場館與休館日），沒有活動列表的。
- 列表有類別（演講研習／其他活動／藝文展演／電影欣賞／說故事）與館別，但沒有名額、沒有報名狀態。
- **不接**：12 筆的量不值得，且分頁機制未解出。下一輪可從詳情頁 id 連號（實測 9721～10098）反推，或找報名子系統。

### 2.3 臺中市立圖書館：**次優先，建議下一輪接**

- 活動報名列表：`GET https://www.library.taichung.gov.tw/registration/index?Parser=99,3,91,28,44`，伺服器端 `<li role="row">` 列表（不是 `<table>`），欄位齊：**館別、標題、活動日期、開放報名時間（起～訖）、公布日期**，詳情 `Details?Parser=99,3,91,28,44,,,<id>`。實測第 1 頁 ~25 筆、**共 2 頁**。
- 另有真的 RSS：`GET https://www.library.taichung.gov.tw/ActiveRss?Parser=9,3,39,27,,,,,,,,1`，`application/rss+xml`，**20 筆**，末位參數是頁碼（有 1、2 兩頁）。
- 館別下拉有 **49 個分館**（總館、大墩、精武、葫蘆墩…），可直接當館別對照。
- 名額：列表沒有，需進詳情頁確認。
- **建議接**（本輪未接，純粹是先做投報比更高的兩支）。它是六都裡除臺南、新北外唯一有「開放報名時間」結構化欄位的，且量不大、解析單純。

### 2.4 高雄市立圖書館：RSS 有，但內容是圖文新聞稿

- `GET https://www.ksml.edu.tw/NewsRss.aspx?m=<1..6>`，`application/rss+xml`。實測 m=1 30 筆、m=2 28 筆（**6.5 MB**，內嵌大量 base64 圖片）、m=3 30 筆（各館活動）、m=4 30 筆、m=5 30 筆（新聞稿）、m=6 3 筆。每個 feed 上限 30 筆、滾動。
- m=3 最接近「活動」，但 `description` 是整篇帶行內樣式與 `<img>` 的 HTML，活動時間／地點／講師全寫在圖文裡（例「◾️活動時間：115/09/27(日)上午10:00-12:00」）。**沒有結構化的日期、名額、報名狀態欄位。**
- **不接**：和北市圖同一個問題（新聞稿模組），而且 feed 只留最新 30 筆、`description` 肥大。建議改找高市圖的活動報名子系統。

## 4. 本輪沒有做、建議之後處理的順序

1. **wSite 六縣市共用解析器**（苗栗／雲林／嘉義縣／嘉義市／宜蘭／澎湖）——投報比最高，一支吃六縣市，且是報名模組不是新聞稿。先逐站解出 `ctNode`。
2. **`taichung-library-registration` 臺中市立圖書館活動報名**——欄位已確認齊全（館別／活動日期／開放報名時間），2 頁、解析單純，49 個分館的對照表現成。
3. **北市圖改走詳情頁或報名系統**——量最大（RSS 就 100 筆）但 RSS 沒有日期欄位，必須換端點才值得接，不要硬解自由文字。
4. **新北的 3 筆【全市】跨館活動補館別**——實際館名寫在場次名稱裡（「汐止大同分館(創藝空間)」），對場次名稱再做一次精確比對即可，但要精確比對、不要模糊猜。
5. 高雄、桃園：等找到報名子系統再說，現有的新聞稿／12 筆列表都不值得接。
